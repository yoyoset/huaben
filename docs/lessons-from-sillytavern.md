# 前身踩坑记录(SillyTavern 小说连载模式,2026-09-25 ~ 09-28)

全部是实测得来,带当时的数字。话本里同类问题直接按这里的结论处理。

## LLM 生成

| 现象 | 根因 | 结论 |
|---|---|---|
| 3000 字长章**后半段标点全部消失**,句子粘成一片 | `frequency_penalty`/`presence_penalty` = 0.15。标点是最高频 token,长文里被一路压低 | **长文生成两项惩罚必须为 0**。短回复看不出问题,长章必现 |
| 回复**正文为空**,看起来"卡住了",重发才好 | 思考模型把 `max_tokens` 全花在 reasoning 上(MiMo 一次 6000 字思考;DeepSeek 偶发 4814 字) | 小说写作关掉思考;OpenRouter 上要显式发 `reasoning.effort = "none"`(酒馆里得"最低"+关显示思维链才会发 none,单独"最低"只发 low);`max_tokens` 留足余量 |
| MiMo 2.6 Flash 每轮 45~145 秒 | 无视 effort=low,仍长时间思考 | 同卡同输入 **DeepSeek V4.1 Flash 15~20 秒**、恐怖感与文笔更好;关思考后 8~12 秒。默认 DeepSeek V4.1 Flash |
| 关掉思考后**漏掉格式要求**(状态栏) | 格式要求写在远处的设定里,不思考时容易丢 | 关键格式/约束放在**紧贴输出位置**的指令里(后置指令) |

## 遗忘与一致性

| 现象 | 根因 | 结论 |
|---|---|---|
| 配角"阿蘅"被写成"阿萤" | 人物条目是关键词触发,名字没出现就不进上下文 | 小说场景下**全部人物设定常驻**;话本里由账本按章纲挑选相关人物,但核心人物永远带上 |
| 另一本书的人物"江烬"串进《诡仙》 | 标题页里写了示例"让江烬早点出场",模型当成了指令 | **示例文本也是 prompt**,不能出现不属于本书的专名 |
| 滚动摘要压掉细节和伏笔 | 摘要是有损压缩,且不区分"细节"和"伏笔" | 伏笔需要结构化账本单独追踪,不能只靠摘要(→ 架构 3.1) |

## 节奏

| 现象 | 根因 | 结论 |
|---|---|---|
| "剧情太慢":15 轮 AI 回复,剧情内只过了 72 分钟(~7 分钟/轮) | 卡用"72 小时实时倒计时"结构 + 提示词没规定每轮推进粒度;用户每轮只回 1 个字选选项 | 不是模型问题。**规定每次输出必须完成一个完整剧情节拍**、过渡用时间跳跃、按阶段而非时钟推进 |
| 用户不想"玩",只想"看" | 交互式跑团对用户是负担 | 话本的定位:读者不是合著者,默认一键连载 |

## 朗读

| 现象 | 根因 | 结论 |
|---|---|---|
| 系统语音锁屏就停 | 浏览器 speechSynthesis 实时朗读 | 预生成音频文件 + `<audio>` 播放(→ 架构 1) |
| Edge TTS 插件默认输出 **WebM/Opus** | 插件写死格式,iOS 兼容性存疑 | 直接要 **MP3**(`audio-24khz-48kbitrate-mono-mp3`);话本里用 Python `edge-tts` 直接指定格式,不走酒馆插件 |
| 网络 | 13 能直连 github 与 `speech.platform.bing.com`(2026-09-28 实测) | 保底语音在 13 上可直接跑 |

Edge 中文音色:晓晓(温暖女声)、晓伊(活泼女声)、云健(激昂男声)、云希(阳光男声)、云夏(可爱童声)、云扬(播音腔)。
