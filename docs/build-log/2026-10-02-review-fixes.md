## 设计取舍

- **规整 vs 拒绝**(#1):常见无害变形(字符串当单元素、"否"当 false、"#3"当编号)就地修正,
  因为真实模型这样输出的概率很高,拒绝等于白扔一稿正文;真正无法理解的才算失败。没给的人物字段保持缺省,
  否则 merge 会用默认值覆盖旧状态(把死人改回活人)。
- **事实压缩**(#6):与章节同一策略——按故事结构(卷)压缩,不按条数截断。代价是封卷多一个字段要模型产出;
  为防丢事实,有事实却给空定本视为解析失败。
- **伏笔上限**(#7):上限只作用于"展示",账本不删;未展示的报数量,规划时可看到最多 30 条积压。
- **质量底线**(#8):只拦"明显不是一章小说"的稿子,不评判好不好看;阈值(40% 篇幅、1/60 标点密度)是起点,
  需要真实 API 数据校准。
- **人话错误**(#9):后台失败说"会自动重试,不用管";用户当场的操作说"请稍后再试一次",不乱承诺。

## 踩坑

- **Bash 工具里的 heredoc 会吞反斜杠**:`python - <<'PYEOF'` 脚本里写 `\\n`,传到 Python 时只剩 `\n`(真换行),
  导致含 `\n` 字面量的锚点匹配失败(本轮 4 次)。含反斜杠的源码修改一律用 Edit 工具,不用脚本 replace。
- #8 加入篇幅检查后,原有 25 个测试的假正文("正文")被拦下——测试统一用很小的 `chapter_words`,e2e 用 1000。
