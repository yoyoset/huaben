## 1. 运维可见性

做了:`huaben.__version__ = "0.2.0"`;`api/routes_system.py` 接管 `/api/health`,报告版本、数据库迁移版本(当前/最新)、
worker 是否在跑(轮数、最后一次巡检时间)、LLM 是否已配置与模型名、TTS 实现;`Worker.status()`。

决策:
- 没配 LLM 密钥时 health 仍返回 200:它是"服务活着"的探针,docker healthcheck 依赖它;返回非 200 会导致容器被反复重启。
  "能不能生成"通过 `llm.configured` 如实报告。
- 只报告密钥"配了没有",测试断言响应里不含密钥原文。

暂不处理:worker 只报告"在转",不报告每本书的退避状态(需要时再加)。

## 2. 配置校验

做了:`Settings` 每个数值加范围(`Field(ge/le/gt)`);跨字段规则(退避上限 ≥ 起始、`CHAPTER_MAX_TOKENS` ≥ `CHAPTER_WORDS`);
base URL 必须是 http(s) 并去掉末尾斜杠;`describe_config_error()` 把校验错误翻成"哪个环境变量、为什么、当前值";
`python -m huaben` 遇到坏配置以退出码 2 退出、只打人话不打堆栈(子进程实测)。

决策:
- 范围下限放得宽(`chapter_words ≥ 1`、`tts_chunk_chars ≥ 1`),因为测试要用极小值;真正要拦的是 0/负数/明显错配。
- `max_tokens < 目标字数` 视为配置错误而非警告:这种配置下每章必然被截断、写满几稿后失败,是确定的坏状态。

暂不处理:没有校验 `LLM_MODEL` 是否真实存在(需要调 OpenRouter,属于对外请求;运行时 400 会被 human_errors 翻成"检查 HUABEN_LLM_MODEL")。

## 3. 查询效率

做了:`repo.chapter_index`(目录:不含正文,一条 LEFT JOIN 带出是否有音频)、`repo.count_accepted`;
书架计数、章节目录、`load_context` 的本卷章摘要、封卷取摘要、卷满判断全部改用它们。`accepted_chapters` 保留(含正文),注释说明何时不该用。

实测(500 章 × 约 3000 字,本机 SQLite,20 次平均):
| 操作 | 旧 | 新 |
|---|---|---|
| 章节目录(含"是否有音频") | 30.2 ms(读全部正文 + 每章一次音频查询,N+1) | 6.7 ms |
| 定稿章计数 | 19.1 ms | 4.2 ms |

书架页每本书都要计数,`load_context` 每写一章都要读本卷章摘要——这两处随连载变长线性变慢,现在不读正文。

暂不处理:计数 4 ms 对 500 章仍偏高(COUNT 走的是行扫描);真到几千章再考虑 (book_id, status) 索引——那需要一条迁移。

## 4. 前端·等待态自动刷新

做了:
- 后端 `book_view` 增加 `generating`(连载中且缓冲未满 = 后台还会继续补货),前端据此决定是否轮询。
- `web/js/poll.js`:有上限的轮询;间隔由纯函数 `logic.pollDelay` 决定(5→10→15→20→30→45→60 秒封顶,40 次后放弃并提示);
  换页面时 `main.js` 统一 `cancelAllPolls()`,不会在别的页面背后一直打请求。
- 阅读页:第一章没写好 → 自动等待并打开;下一章还在写 / 本章语音还在准备 → 轮询目录,**就地**更新按钮和提示,不重绘正文(不打断阅读位置)。
- 书架:有书在生成时自动刷新列表,显示"正在写…",全部备好后停止。
- sw.js 壳清单加入 poll.js,缓存版本升到 v2。

**真实浏览器验证**:种子库只有第 1 章且无音频 → 阅读页显示"下一章还在写"(禁用)、"语音还在准备";
后台脚本插入第 2 章与第 1 章音频后,第一次轮询(5 秒)即把按钮变为可点的"下一章 →"、清掉语音提示,正文未重绘。
书架显示"· 正在写…"。控制台只有已知的内置浏览器 SW 注册错误。

暂不处理:页面在后台(切走标签页)时仍按间隔轮询;次数有上限,开销可接受,需要时再按 `visibilitychange` 暂停。

## 5. 前端·阅读体验

做了:
- `web/js/reading_prefs.js`:字号 A-/A+、行距档位切换,存在 localStorage(读写都 try/catch,不可用时照常显示默认值);
  通过 CSS 变量 `--read-size`/`--read-leading` 生效,`main.js` 在首次渲染前应用,避免跳动。
- 纯函数(`logic.js`):`stepFont`(±1,夹在 14~28,坏值回默认)、`nextLeading`、`chapterMark`(当前/已读/未读)。
- 目录:当前章高亮"← 正在读"并带 `aria-current`,已读(≤ 最远进度)变淡,展开时自动滚到当前章;标题显示已读章数。
- 章末"↑ 回到顶部"。sw 壳清单加入新模块,缓存版本 v3。

**真实浏览器验证**:A+ 两次、行距一次 → 正文 18px→20px、行高 35.1px→44px,localStorage 写入 `{fontSize:20, leading:2.2}`;
换到另一章后设置仍生效;在第 2 章时目录为[第1章=已读, 第2章=正在读],回到第 1 章时第 2 章仍标为已读(最远进度=2)。

暂不处理:没有夜间/日间手动切换(目前跟随系统);偏好不跨设备同步(本机记忆足够家用)。
