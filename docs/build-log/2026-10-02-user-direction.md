# 2026-10-02 用户改定方向后的三项改动

背景:用户看完持续完善的汇报后提出(原话摘要):"每个人的 profile 是不一样的(我老婆是她的,我是我的)";
"配音用我电脑 3060 跑的本地 TTS,不要死磕 edge-tts;电脑没开就告知、提醒开机,我的电脑我自己控制,不急";
"主要还是在故事质量;稳定性和花钱方面提醒就好,不用限制那么死,这个我都知道"。

## 1. 花费只提醒不拦(d755720)

- `HUABEN_SPEND_REMIND_USD_24H`(默认 2):过去 24 小时全部书合计超过即在书架显示提醒,生成照常。
- `HUABEN_SPEND_LIMIT_USD_24H` 默认改为 0(不设硬上限);拦截逻辑保留为可选项(用户偏好:新旧并行保留)。
- `/api/spend` + `logic.spendNote`:超过提醒线或"有调用上游没报费用"时提示。

## 2. 每人一个书架(4f4418b)

- 迁移 7:`profiles` 表 + `books.profile_id`;已有的书归到默认读者"我"——升级不丢书(测试用 v6 旧库验证)。
- 打开先选"谁在看"(不要密码,Tailscale 已挡外人),选择记在本机;顶栏显示当前读者,点它换人。
- 字号/行距按人记。本机记着的读者在服务器上已不存在(比如恢复了旧库)时自动回到"谁在看"。
- 不做:删除读者(删人要处置他的书,与"不随手删内容"冲突)、书在人之间共享/转移。

## 3. 配音以电脑为主(ce89d61 + 电脑端程序)

- 先查清事实再设计:爱读(aidulc)的"高质量朗读"是 **Kokoro-82M**,由爱读桌面程序拉起的命令行进程(stdin/stdout),
  不是网络服务;而且**只配了英文**(语言表里英文→`a`,另一门→`j`),本机只下载了英文音色 `af_heart`,
  中文前端依赖(jieba/pypinyin/cn2an)也没装。用户回复:Kokoro 只是举例,中文要用对应的中文模型。
- 服务器(`HUABEN_TTS_MODE=pc`,默认)不自己配音,出任务队列;电脑上的程序**拉取**任务、交 MP3(电脑不用开端口)。
  任务顺序:每本书按读者接下来要听的,多本书轮流取(`voice_queue.interleave`)。
- 两份音频并存:basic=edge、hq=电脑;播放优先 hq,文件丢了退到另一份;音频地址带版本(`?v=1_0004.hq.mp3`),
  升级后浏览器不会继续播缓存里的旧版。
- 电脑离线(10 分钟没来取任务):书页与书架提示"有 N 章在等电脑配音,请打开电脑上的配音程序",
  书页可点"先用 edge-tts 配"(只配一份音频都没有的章;电脑开机后照样升级)。电脑在线时显示"正在配音"。
- 电脑端程序 `pc_worker/huaben_voice`:一次取一章 → 合成 → 交回;没任务歇 30 秒;出错指数退避、不退出。
  引擎接口 `synthesize(text) -> MP3 bytes`,目前只有 `fake`。
- MP3 编码:实测爱读环境里的 soundfile 0.14 / libsndfile 1.2.2 能直接写 MP3(24kHz 写出的是 MPEG-2 帧 `FF F3`),
  服务器的 `is_mp3` 按帧同步字判断,接受。

验证:服务器侧 9 个测试 + 电脑端 5 个测试(对着真的 FastAPI 接口端到端跑:按听的顺序取、配完队列清空、令牌、
出错退避不退出);浏览器用替身 TTS 走通"提示 → 先用 edge → 电脑上线显示正在配 → 交 MP3 → 播电脑版"。

## 踩坑

  所以没有写坏文件;改用 Edit 工具完成。

  以后临时服务器一律注入 FakeLLM,不碰外网。
