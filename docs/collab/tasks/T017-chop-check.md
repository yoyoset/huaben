# T017 碎句检查:句子被逗号切碎的稿子,打回

依赖:无。

## 为什么

2026-10-03 回看《弄假成真》第 3~30 章(架构方在同一个对话里一口气写的):句子越写越碎。
实测每百字的全角逗号数:第 1~8 章约 7,第 12~18 章 9~10,第 19~30 章 10.3~12.4。第 30 章满篇是
"陈皮的血,一下子,冲上了头""木板,翻开了"这种句子,看着做作,配音会一顿一顿。

原因是"自己学自己":前面写出的章留在上下文里,下一章照着模仿并加码。写作模型按章写时也带着最近 3 章原文
(`recent_chapters_in_prompt`),同样会漂。现有机械检查没有一项量这个,所以加一项。

## 已定的方案

### 1. 纯函数(新建 `huaben/pipeline/chop.py`)

```python
CHOP_LIMIT = 9.0        # 每百字全角逗号数超过它就算切碎(实测:正常的章 6~8,切碎的章 10 以上)
CHOP_MIN_CHARS = 500    # 太短的文本不量(样本小,数字不稳)


def comma_density(text: str) -> float:
    """每 100 个非空白字符里有几个全角逗号"，"。空文本返回 0.0。"""


def chop_problems(text: str) -> list[str]:
    """超过 CHOP_LIMIT → 一条打回理由;否则空列表。非空白字符不足 CHOP_MIN_CHARS → 空列表。"""
```

- "非空白字符"= `re.sub(r"\s", "", text)` 的长度。只数全角逗号 `，`(U+FF0C),不数顿号、句号、半角逗号。
- 打回理由的原文(一字不改,`{d}` 保留一位小数):

  `句子被逗号切得太碎（每百字 {d} 个逗号，正常是 6~8 个）：主语和谓语之间不要加逗号，“他的手，停了”要写成“他的手停了”；不要把一句话切成一串两三个字的小段。请把句子接顺再写一稿。`

  (这句里的标点全是全角,引号是中文弯引号;照抄,测试里断言它以"句子被逗号切得太碎（每百字"开头。)

### 2. 接进写章流程(`huaben/pipeline/chapter.py`)

- `_draft_until_accepted` 里 `problems = (...)` 那个加法式子的末尾加 `+ chop_problems(body)`(模型写的稿:超了就打回重写)。
- `_imported_text` 里"只留痕不打回"的那个 `for p in (...)` 加法式子的末尾同样加 `+ chop_problems(body)`(导入稿:只留痕)。
- 不改提示词。`chapter.py` 现在 182 行,这次只加一行 import 和两处 `+ chop_problems(body)`。

### 3. 测试(新建 `tests/test_chop.py`)

- `comma_density`:`"他的手，停了。"`→ 7 个非空白字符、1 个逗号 → 约 14.29;空串 → 0.0;半角逗号不计;换行与空格不计入字数。
- `chop_problems`:600 字、每 20 字一个逗号(密度 5)→ 空;600 字、每 8 字一个逗号(密度 12.5)→ 一条,且以"句子被逗号切得太碎"开头、含"12.5";
  同样密度但只有 200 字 → 空。
- 流程:用 `tests/scripted_llm.py` 现有的办法跑一章,第一稿正文是切碎的(密度 > 9)、第二稿正常 →
  第一稿被打回(运行记录里有以 `draft: 句子被逗号切得太碎` 开头的 rejected 记录)、第二稿定稿。
  需要给 `ScriptedLLM` 加开关才能做到的话,加一个默认关闭的参数,不改它现有的行为。
- 导入稿:导入一篇切碎的正文 → 章照常定稿,运行记录里有 `导入正文的提醒(未打回):句子被逗号切得太碎…`。

## 这次不做

- 不量"一动不动""一级一级"这类口头禅。
- 不改已定稿的章。
