# T002 配音:在显卡上实测"一块多长最稳"

依赖:T001 通过。

## 为什么

T001 把块长先定在约 200 字。用户希望一次生成得越长越好(声音越连贯)。但越长越容易失控/漂移。
到底 200 还是 400 还是更长,**不猜,测**:同一章、同一音色,三种块长各配一遍,比数字,并留样音给用户听。
最终选哪个由架构方和用户定,**本卡只出数据,不改默认值**。

## 前提(需要用户配合)

这张卡要占用显卡。开工前**先问用户**:"T002 要用显卡跑约 30 分钟,请先关掉桌面上的『话本配音』窗口,关好了告诉我。"
用户没确认之前不要跑(两个程序抢显卡,数字不可信,还会拖慢正在配的章)。用户说现在不方便:状态改「卡住」,
报告里写"等用户空出显卡",去做下一张卡。

## 已定的方案

新建脚本 `pc_worker/bench_chunks.py`(不是测试,不进 pytest;≤ 200 行),用 `pc_worker/.venv-qwen/Scripts/python.exe` 运行:

```
pc_worker/.venv-qwen/Scripts/python.exe pc_worker/bench_chunks.py samples/voice_bench/chapter.txt
```

脚本做的事:

1. 读入章节文本。加载一次引擎:`Qwen3Zh(voice="女声")`(来自 `huaben_voice.qwen3_zh`)。
2. 对下面三种切法各配一遍,**每一块单独计时、单独保留音频数组**(直接调引擎的 `_once(seg)`,不走重试,这样才能数出失控次数):

   | 名字 | 怎么切 |
   |---|---|
   | `old` | 旧切法:`[s for p in segments(text, 200) for s in p]` |
   | `c200` | `chunks(text, 200, 300)` |
   | `c400` | `chunks(text, 400, 500)` |

3. 每种切法算出并打印一行(同时写进 `samples/voice_bench/result.txt`):
   - 块数;
   - 失控块数:`runaway(seg, 秒数)` 为真的块数(函数已在 `qwen3_zh.py`);
   - 总音频秒数、总耗时秒数;
   - **音高一致性**:每块的音高中位数(Hz),然后报告这些中位数的 **最小值、最大值、极差、标准差**。
     音高用 `librosa.pyin(y, fmin=60, fmax=500, sr=sr)` 取有声帧的中位数;不到 1 秒的块跳过不算(太短测不准),
     并打印"跳过了几块"。`.venv-qwen` 里没有 librosa 的话**先问用户**能不能 `pip install librosa` 装进 `.venv-qwen`,不要自己装。
   - **语速一致性**:每块的 `字数 / 秒数`,报告最小值、最大值、标准差。
4. 每种切法把**前 120 秒**的音频存成 `samples/voice_bench/<名字>.mp3`(用 `kokoro_zh.encode_mp3`),给用户听。

`token_cap` 对 400~500 字的块会算出超过 2048 的上限,这是预期的(`_once` 已经把 `max_new_tokens` 显式传给模型)。
如果模型对超过 2048 报错:把报错原文贴进报告,`c400` 这一行写"模型拒绝",其它两行照常。

## 验收标准

1. `samples/voice_bench/result.txt` 存在,三种切法各一行,数字齐全;内容原样贴进报告。
2. `samples/voice_bench/old.mp3`、`c200.mp3`、`c400.mp3` 三个文件存在(`samples/` 不进 git,所以报告里写清每个文件的大小)。
3. `python -m pytest -q` 仍然全过(本卡不该影响任何测试)。
4. 报告里**只列数字,不下结论**"哪个更好"——那是架构方和用户的事。

## 这次不做

- 不改 `MAX_SEG_CHARS`,不改 `HuabenVoice.ini`,不改采样温度等任何生成参数。
- 不测别的引擎、别的模型。
- 跑完不要帮用户重新打开『话本配音』,在最后告诉用户"显卡用完了,可以重新打开"。

## 审核记录

**通过(2026-10-03)**。同一章(3972 字)三种切法的实测:

| 切法 | 块数 | 失控 | 各块音高中位数的极差 / 标准差 | 语速(字/秒)最小~最大 / 标准差 | 耗时 |
|---|---|---|---|---|---|
| 旧(按段落) | 133 | 0 | 288 Hz / 34 | 2.50~12.50 / 1.37 | 418 秒 |
| 合并到 200 字 | 21 | 0 | 40 Hz / 8 | 4.95~5.89 / 0.27 | 360 秒 |
| 合并到 400 字 | 10 | 0 | 39 Hz / 11 | 5.31~6.13 / 0.25 | 346 秒 |

结论(架构方):"声音对不上"确实是切得太碎造成的,合并后音高极差从 288 Hz 降到 40 Hz、语速波动降到五分之一。
200 与 400 在一致性上没有差别;400 只快 4%,而一旦某块失控,重来的代价翻倍(本次只测了一章,0 次失控不代表不会)。
**默认保持 200**,除非用户试听后明显更喜欢 c400。样音:`samples/voice_bench/old.mp3`、`c200.mp3`、`c400.mp3`。
